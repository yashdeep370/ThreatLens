- [ ] Open http://127.0.0.1:8000 and check the sidebar says **Models ready** and **AI: gemini/groq**
- [ ] Chrome extension loaded (`chrome://extensions` → ThreatLens Website Guard, enabled)
- [ ] Optional: turn off Avast "HTTPS scanning" so certificates show the real issuer
- [ ] Close unrelated tabs; zoom the browser to 110–125% so the examiner can read it
- [ ] Have `reports/confusion_matrix_XGBoost.png` and `reports/metrics.json` ready to open

## Likely examiner questions

**Q: Which dataset and how much data?**
CIC-IDS2017 (Canadian Institute for Cybersecurity): 2.8M flows over 5 days. We removed 329,851
duplicates (11.7%), capped classes → 359,150 flows, 69 features, 80/20 stratified split
(287,320 train / 71,830 test). URLs: 641,119 unique from the Kaggle Malicious URLs dataset.

**Q: 99.94% accuracy is suspicious. Why so high?**
CIC-IDS2017 attacks were generated in a lab and are very separable, and train and test come from the
same network. On real networks it would be lower. That's why we report per-class metrics, add an
anomaly detector, and never claim 100% security.

**Q: Why XGBoost over Random Forest?**
Both were near-identical (macro F1 0.9994 vs 0.9990); XGBoost was slightly better and trained faster
(31 s vs 49 s). Gradient boosting is strong on tabular data.

**Q: Why not just accuracy?**
With imbalanced data, "predict everything benign" gets high accuracy but catches nothing.
We use precision, recall and F1 per class. Recall matters most: a missed attack costs more than a false alarm.

**Q: How did you handle class imbalance?**
Capped the majority classes (Benign 200k, attacks 50k each), stratified splitting, and balanced class
weights in Random Forest. Brute force is the smallest class (9,150) and still has F1 0.9997.

**Q: What does the Isolation Forest add?**
It's trained only on normal traffic, so it can flag unusual traffic of unknown types that the classifier
was never trained on. Its threshold is calibrated to 1% false alarms, and it only raises an incident above 2%.

**Q: Why didn't the anomaly detector catch brute force or port scans?**
A single brute-force or scan connection looks like a normal short connection. Those attacks are visible
only as patterns across many flows, which the supervised classifier learns. The two models complement each other.

**Q: How is "confidence" calculated?**
It's the classifier's predicted probability for its chosen class, averaged over an incident's flows.
It shows how strongly the traffic matches learned patterns, not a guarantee.

**Q: How is the security score calculated?**
Start at 100 and subtract per incident: severity weight (Critical 40 / High 25 / Medium 10) × confidence ×
volume factor (0.5 below 10 flows, 0.75 below 100, 1.0 otherwise). Groups of fewer than 5 flows are treated as
isolated detections with no penalty.

**Q: What is RAG here?**
Retrieval-Augmented Generation: for each question we retrieve the most relevant chunks (TF-IDF similarity)
from 51 knowledge chunks (30 from MITRE ATT&CK, plus our playbooks and documentation) and give them to the LLM
with the current analysis. Answers are grounded and cite sources.

**Q: What if the LLM hallucinates?**
The system prompt restricts it to the provided context. The evidence and recommendations in reports are
computed or curated, not generated, so the LLM only explains them.

**Q: Isn't the URL model's reputation list cheating?**
No, it's a standard layer (browsers use Safe Browsing and allowlists). It's transparent: the report shows
when it overrides the model, and a very confident malicious verdict (≥90%) is still flagged on a trusted domain.

**Q: Can it detect attacks on any website?**
No, and that's by design. Detecting a DoS on a server needs that server's traffic. The Website Check makes
one normal request (like a browser) to assess HTTPS and headers; it never scans. It also blocks requests to
internal IP addresses (an SSRF protection).

**Q: Why doesn't it block attacks automatically?**
False positives could block legitimate users. Human-in-the-loop is the safer, responsible design for
version 1: detect, explain, recommend, and the human decides.

**Q: How would you deploy it for real?**
Run CICFlowMeter on a network tap or server to produce flows continuously, feed them to the API, and host
the backend online (Render / Railway). The extension's backend URL is configurable in its settings.
